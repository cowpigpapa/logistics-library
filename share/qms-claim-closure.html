2. 화면 배치

  • 화면 전체: 세로 3단 — Progress & Result → Claim Settlement → CAPA. 섹션 사이 검은 구분선 유지.
  • Progress & Result, CAPA: 현행 스플릿(Split screen) 50:50 (왼쪽 입력, 오른쪽 이력) 그대로.
  • Progress & Result 오른쪽 이력(Contents): 머리글 + 3줄이 보이는 높이로 고정, 넘치면 세로 스크롤 (머리글은 고정). 오른쪽 패널의 아래 끝은 왼쪽 패널과 맞춤.
  • Claim Settlement 머리: 빨간 탭 대신 글자 제목 * Claim Settlement ⓘ (기존 Actual Loss Cost와 같은 모양) + 오른쪽에 요약 바 (검은 '요약 (USD)' 라벨 + 5칸) + 오른쪽 끝 No Claim. 요약 바는 아래 표 영역과 살짝 띄운 별도 카드.
  • Claim Settlement 본문: 스플릿(Split screen) 50:50 — 왼쪽 지불내역, 오른쪽 회수내역.
  • 각 표 위: 제목 오른쪽에 한 줄 안내, 맨 오른쪽 + / − 버튼.
  • 화면 폭이 약 1,150px 보다 좁으면 지불 → 회수 순서로 위아래로 쌓이고, 표는 가로 스크롤.
  • 권장 컬럼 폭(px, 화면 폭 1,600px 기준): 지불 — 선택 30 · 주체 110 · 방법 나머지 · Currency 80 · 금액 84 · USD 환산 84 · Remark 112. 회수 — 주체 컬럼 없이 방법이 나머지 폭.

5. 요약 계산 (USD 기준)

항목계산
전체 클레임 비용이 건의 총 클레임 금액. 실제 화면 위쪽에 이미 있는 전체 비용 입력 칸의 값을 보여 줌. 미입력이면 당사지불 + 보험사·제3자 부담을 자동으로 넣고 회색 글씨에 '자동' 표시 (직접 입력하면 그 값). '자동' 표시 자리는 늘 비워 두어 요약 폭이 바뀌지 않게. No Claim이면 0. 시안에서는 임시로 이 칸에서 입력 — 괜찮으면 이 칸을 입력 칸으로 사용 (8번 확인 필요)
당사지불지불내역 중 지불주체 = 당사 인 행(P1~P4)의 USD 환산 합계
보험사·제3자 부담지불내역 중 지불주체 = 당사 보험사·협력사·고객사 인 행(P5)의 USD 환산 합계
당사회수회수내역 전체(R1·R2·R4·R5)의 USD 환산 합계
당사 순손실당사지불 − 당사회수 · 음수(회수가 더 많음)면 '당사 순이익'으로 이름을 바꾸고 절댓값 표시
  • 표시: USD, 천 단위 콤마, 소수 2자리.
  • 행 추가·수정·삭제, SAP · CY Cost KPI 조회 결과가 바뀌면 바로 다시 계산.
  • 보험사·제3자 부담과 전체 클레임 비용은 당사 순손실 계산에 들어가지 않음.
  • 시안 페이지의 노란 '원천 데이터 (임시 입력)' 칸은 시연용입니다. 화면 위쪽 전체 비용 칸과 SAP · CY Cost KPI 조회 값을 대신 넣어 보는 곳이며 실제 화면에는 넣지 않음.

6. + / − 버튼

  • 위치: 각 표 오른쪽 위 (지불 표, 회수 표에 각각).
  • 지불 + : 고정 행(P1~P3) 아래에 행 추가 (4번째 행부터). 지불주체 기본값 '당사' → 지불방법 P4 자동. 주체를 당사 보험사·협력사·고객사로 바꾸면 P5 자동.
  • 회수 + : 고정 행(R1·R2) 아래에 행 추가. 회수방법은 R4 / R5 중 선택.
  • 새 행의 Currency 기본값은 USD.
  • − : 체크한 행 삭제. 체크한 행이 없으면 비활성. 고정 행에는 체크박스가 없어 지울 수 없음.
  • 머리글 체크박스: + 로 추가한 행만 전체 선택 / 해제. 추가한 행이 없으면 비활성.

7. No Claim (비용 없음)

  • 위치: Claim Settlement 줄 오른쪽 끝 (다른 섹션의 버튼 자리와 같음). 테두리 있는 버튼형 체크박스 ☐ No Claim (비용 없음).
  • 체크하면: 화면 전환 없음 — 지불·회수 표와 + / − 버튼은 그대로 보임. 요약은 모든 칸 0.00 (전체 클레임 비용도 0, 입력 막음).
  • 체크 조건: 비용 금액이 하나도 없을 때만 — 조회 금액(P1·P2·R1·R2 SAP, P3 CY Cost KPI), + 로 추가한 행의 금액, 직접 입력한 전체 클레임 비용이 모두 비어 있어야 함. 하나라도 있으면 체크박스 비활성, 마우스를 올리면 이유 표시.
  • 금액 없는 추가 행은 그대로 두고, 저장할 때 제외.
  • 체크 해제: 언제든 가능. 체크 중에 표의 + 를 누르면 No Claim 자동 해제.
  • No Claim으로 저장한 뒤라도 SAP · CY Cost KPI 조회 금액이 들어오면 No Claim 자동 해제, 이력에 'No Claim 자동 해제 (비용 금액 들어옴)' 기록. 추가 행에 금액을 입력해도 같음.
  • 저장 · Result Close: 금액이 있는 행 1개 이상 또는 No Claim 체크 중 하나가 아니면 막음 (비용 누락 방지).
  • 데이터: Claim 여부(Y/N) 따로 저장 → 'No Claim 건수'와 '비용 미입력 건수'를 나눠 집계.
  • 이력(Contents): 체크·해제를 한 줄씩 남김 (제안). 예: [NCL] … No Claim 체크

8. 개발 전 확인 필요

  1. 환율 출처와 기준일 — 일자 컬럼이 없어져 USD 환산 기준일을 따로 정해야 함 (예: 입력일, 전표일, 부적합 발생일).
  2. 전체 클레임 비용 입력 위치 — 화면 위쪽의 기존 칸을 그대로 쓰고 요약에는 보여 주기만 할지, 요약의 이 칸을 입력 칸으로 쓸지. 두 곳에서 입력하면 값이 어긋나므로 한 곳만.
  3. 조회 시점 — SAP(P1·P2·R1·R2)와 CY Cost KPI(P3) 금액을 화면을 열 때 자동으로 불러올지, 버튼으로 불러올지.
  4. P3 CY Cost KPI 연동 범위 — 가져올 금액(DEM/DET/STG 합계인지 항목별인지)과 통화, Remark에 보여 줄 참조번호.
  5. R3 체화료 환입 — 회수 + 선택지(R4·R5)에서 빠짐. 필요하면 고정 행 또는 선택지로 추가.
  6. 회수처 정보 — 컬럼을 없앴으므로 필요하면 Remark에 적을지.
  7. 기존 Actual Loss Cost 데이터 이관 — 기존 Pay Amount → P1 또는 추가 행, Recovery Amount → R1 또는 추가 행으로 옮길지.
  8. 기획안의 'Estimated' 표시, 책임 판단(전액 인정 ~ 협의 중), 상태(접수 ~ 종결) — 이번 화면에 넣을지, 넣으면 위치.
  9. No Claim 기본값 — 처음엔 항상 체크 안 함으로 할지, 사고 유형에 따라 자동으로 정할지.
