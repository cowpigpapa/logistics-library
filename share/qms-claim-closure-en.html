2. Layout

  • Whole screen: three stacked sections — Progress & Result → Claim Settlement → CAPA. Keep the black dividers between sections.
  • Progress & Result and CAPA: current split screen 50:50 (input left, history right), unchanged.
  • History (Contents) on the right of Progress & Result: fixed height showing the header + 3 rows; longer lists scroll vertically (header stays). The bottom of the right panel lines up with the left panel.
  • Claim Settlement header: instead of a red tab, the text title * Claim Settlement ⓘ (same look as the old Actual Loss Cost label) + the summary bar to its right (black 'Summary (USD)' label + 5 cells) + No Claim at the far right. The summary bar is a separate card with a small gap above the tables.
  • Claim Settlement body: split screen 50:50 — payments left, recoveries right.
  • Above each table: title and guidance on the left, + / − buttons on the right.
  • Below about 1,150px width, the tables stack (payments, then recoveries) and scroll horizontally.
  • Suggested column widths (px, at 1,600px screen width): payments — Select 30 · Paid by 124 · Type (rest) · Currency 88 · Amount 78 · In USD 76 · Remark 104. Recoveries — no party column; Type takes the rest.

6. + / − buttons

  • Position: top right of each table (payments and recoveries separately).
  • Payments + : adds a row below the fixed rows (P1–P3), i.e. from row 4. Paid by defaults to 'LXP' → Payment type P4 is set automatically. Changing Paid by to LXP insurer, vendor or customer sets P5.
  • Recoveries + : adds a row below the fixed rows (R1·R2). Recovery type is chosen from R4 / R5.
  • New rows default to USD.
  • − : deletes the ticked rows; disabled when none is ticked. Fixed rows have no checkbox and cannot be deleted.
  • Header checkbox selects / clears only the rows added with +; disabled when there are none.

7. No Claim

  • Position: right end of the Claim Settlement row (same place as other sections' buttons). Button-style checkbox with a border: ☐ No Claim.
  • When checked: no screen change — the tables and + / − buttons stay visible. The summary shows 0.00 in every cell (total claim cost 0 and locked).
  • Can be checked only when there is no cost amount at all — looked-up amounts (P1·P2·R1·R2 from SAP, P3 from CY Cost KPI), amounts in rows added with +, and an entered total claim cost must all be empty. Otherwise the checkbox is disabled and hovering shows why.
  • Added rows without an amount stay on screen and are skipped when saving.
  • Unchecking: allowed at any time. While checked, pressing + on a table clears No Claim automatically.
  • Even after saving as No Claim, if an SAP / CY Cost KPI amount arrives, No Claim is cleared automatically and logged as 'No Claim cleared automatically (cost amount received)'. Same when an amount is entered in an added row.
  • If there is no cost and No Claim is not checked: a grey hint below the payment table 'If there is no cost, tick No Claim at the top right'.
  • Save · Result Close: blocked unless there is at least one row with an amount or No Claim is checked (prevents missing costs).
  • Data: store Claim Y/N separately so 'No Claim' cases and 'cost not entered' cases can be counted apart.
  • History (Contents): log check / uncheck as one line each (suggestion). E.g. [NCL] … No Claim checked

8. To confirm before development

  1. FX source and reference date — with no Date column, a reference date for the USD conversion is needed (e.g. entry date, voucher date, irregularity date).
  2. Where total claim cost is entered — keep the existing input at the top of the screen and only show it in the summary, or make this summary cell the input. Entering it in two places lets the values drift, so use one.
  3. When amounts are looked up — load SAP (P1·P2·R1·R2) and CY Cost KPI (P3) automatically when the screen opens, or with a button.
  4. P3 CY Cost KPI link — which amount to take (DEM/DET/STG total or per item), its currency, and which reference number to show in Remark.
  5. R3 DEM/DET/STG recovery — not in the recovery + options (R4·R5). Add as a fixed row or option if needed.
  6. Recovered-from information — the column is removed; write it in Remark if needed?
  7. Migrating existing Actual Loss Cost data — move the old Pay Amount into P1 or an added row, and Recovery Amount into R1 or an added row?
  8. 'Estimated' flag, liability decision (fully accepted ~ under negotiation), status (received ~ closed) from the planning draft — include on this screen, and where?
  9. No Claim default — always unchecked at first, or set automatically by irregularity type.
