1한눈에

입력 위치

Irregularity Closure 화면 안 Claim Settlement 구역. 별도 메뉴나 팝업 없음.

화면 배치

사이드바 레이아웃: 본문(PR · CAPA) : History = 7 : 3. Claim Settlement는 맨 아래 전체 폭.

지불 · 회수 표

표는 조회 전용. 입력은 각 표 바로 아래 한 줄 입력칸에서.

코드

지불 P1~P5, 회수 R1 · R2 · R4 · R5. P4 / P5는 지불주체로 자동 결정.

요약

USD 기준 자동 계산. 전체 클레임 비용도 입력 없음 (지불 합계).

No Claim

요약 줄 맨 끝 칸. 금액이 하나도 없을 때만 체크 가능, 체크하면 입력 잠김.

칸계산표시
전체 클레임 비용당사지불 + 보험사 · 제3자 부담숫자만 (입력 없음), 검정
당사지불지불주체 = 당사 (P1~P4)의 USD 환산 합빨강 글씨
보험사 · 제3자 부담지불주체 = 당사 보험사 · 협력사 · 고객사 (P5)의 합진회색 글씨
당사회수회수 전체 (R1 · R2 · R4 · R5)의 합파랑 글씨
당사 순손실 / 순이익당사지불 − 당사회수. 음수면 이름을 '당사 순이익'으로 바꾸고 절댓값손실: 빨강 + 연한 빨강 배경 · 이익: 파랑 + 연한 파랑 배경
No Claim체크 칸 (아래 참고)맨 끝 칸
  • 식 (예: '= 당사지불 − 당사회수')과 '자동' 표시는 화면에 쓰지 않음.
  • 금액 0은 회색 보통 굵기. 천 단위 콤마, 소수 2자리. 행을 추가 · 수정 · 삭제하면 바로 다시 계산.
  • 보험사 · 제3자 부담은 당사 순손실 계산에 들어가지 않음.
  • 시안의 환율은 예시 (1 USD = 1,400 KRW, 1 EUR = 1.08 USD). 실제 출처는 미결 1번.

6No Claim

  • 위치: 요약 줄 맨 끝 칸 '☐ No Claim (비용 없음)'.
  • 금액이 하나라도 있으면 (조회 금액 포함) 회색으로 잠기고, 마우스를 올리면 이유 표시.
  • 체크하면 칸이 검정으로 바뀌고 요약은 모두 0.00, 지불 · 회수 입력칸은 잠김. 체크를 풀면 원래대로.
  • No Claim으로 저장한 뒤 SAP · CY Cost KPI 금액이 들어오면 자동 해제하고 이력에 남김.
  • 저장 · Result Close는 금액 있는 행 1개 이상 또는 No Claim일 때만 (비용 누락 방지). Claim 여부(Y/N)를 따로 저장해 'No Claim 건수'와 '비용 미입력 건수'를 나눠 집계.

7미결 사항

  1. 환율 출처와 기준일 — 입력일 · 전표일 · 부적합 발생일 중 무엇으로 USD 환산할지
  2. 조회 시점 — SAP (P1 · P2 · R1 · R2)와 CY Cost KPI (P3) 금액을 화면 열 때 자동으로 불러올지, 버튼으로 불러올지
  3. P3 연동 범위 — DEM / DET / STG 합계인지 항목별인지, 통화, Remark에 보여 줄 참조번호
  4. R3 체화료 환입 — 지금은 없음. 필요하면 고정 행 또는 선택지로 추가
  5. 회수처 정보 — 컬럼이 없으므로 필요하면 Remark에 적을지
  6. 기존 Actual Loss Cost 데이터 이관 — 기존 Pay Amount → P1 또는 입력 행, Recovery Amount → R1 또는 입력 행
  7. Estimated 표시 · 책임 판단 · 상태 (예전 1차 설계에 있던 항목) — 이번 화면에 넣을지, 넣으면 위치
  8. No Claim 기본값 — 처음엔 늘 체크 안 함으로 할지, 사고 유형에 따라 정할지

정리됨 (2026-11-26) 전체 클레임 비용 입력 위치 → 입력하지 않고 지불 합계로 자동 계산. 고객 · 협력사가 부담한 금액도 지불내역 P5 행으로 들어가므로 따로 칸이 필요 없음.
